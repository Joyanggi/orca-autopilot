# 테스트 전략

앱 초기화 후 실제 실행해 본 명령을 등록합니다. 검증 기록에는 명령, 결과, 사용한 플랫폼이나 기기, 실행하지 못한 이유를 남깁니다.

| 검사 | 대상 | 실제 명령 또는 절차 | 기기 없이 |
| --- | --- | --- | --- |
| 타입 검사와 린트 | 프로젝트 기본 검사 | `npm run typecheck`, `npm run lint` (초기화 후 확정) | 가능 |
| 단위 및 통합 테스트 | 핵심 로직과 데이터 처리 | `npm test` (Jest 등, 초기화 후 확정) | 가능 |
| 프로젝트 진단 | 의존성·설정 호환성 | `npx expo-doctor` | 가능 |
| 번들 생성 | JS 번들이 만들어지는지 | `npx expo export --platform ios` | 가능 |
| 개발 빌드 및 실행 | 앱 설치, 첫 실행, 기본 화면 진입 | `npx expo run:ios --device` | **iPhone 필요** |
| 실기기 확인 | 핵심 흐름과 오류 경로 재현 | [실기기 체크리스트](RELIABILITY-CHECKLIST.md), Mobile MCP | **iPhone 필요** |
| Android 확인 | Android 첫 테스트 범위와 기기 | 플랫폼 범위 확정 후 기입 | 플랫폼 범위 확정 후 |

CI(`{{CI_NAME}}`)는 기기가 필요 없는 검사만 실행합니다. 기기가 필요한 검사는 PR에 "실기기 미확인"으로 남기고, 마스터가 기기 연결이 필요한 시점에 사람을 부릅니다(필수 개입 (g)).
